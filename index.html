Case study · 01

Near Wheels

A single place to book rides, rentals, local services, and buses.

Next.jsTypeScriptPrismaPostgreSQLGeminiRazorpay

The problem

Transport and farm services can be hard to find in one place. Customers often call several providers to compare options, while providers need an easier way to manage bookings and payments.

The approach

I brought seven services into one marketplace: shared rides, vehicle rentals, garages, driving lessons, drone spraying, farm services, and intercity buses. People can compare options and book in one place. An AI trip planner can also suggest routes within a budget.

How I made it reliable

  • Safe bookings. The system reserves a time slot so two people cannot book the same service at once.
  • Checked payments. Payments are matched to the booking total, and a refund is only marked complete after the payment service accepts it.
  • Secure admin access. The server checks a person's role each time they use an admin tool.
  • Abuse protection. Repeated requests are limited using trusted connection details.
  • Safer image uploads. Images are checked and resized before they are saved.

What I built

I built the database, 73 server routes, sign-in, payments, provider and admin pages, the Gemini trip planner, 79 automated tests, and the setup for running the app online.

StatusPrivate build

79 tests passing. Screenshots captured from the running app.

Scale73 route handlers

BookLoop India

A way for readers in India to trade books using credits instead of cash.

The problem

Many readers have books they have finished, while someone nearby may want them. Credits make it easier to trade without agreeing on a cash price each time.

The approach

Readers list a book, request another, and exchange it for credits. The app tracks those credits and updates them when an exchange is confirmed.

How I kept exchanges fair

  • Safe credit transfers. Credits are reserved when an owner accepts, so two requests cannot spend the same credits.
  • Private accounts. Readers only see account and listing details they are allowed to see.
  • Clear exchange steps. Declines, cancellations, and disputes each have a clear outcome.
  • Easy browsing. Readers can filter by book and location, and search engines can find public book pages.

What I built

I built the working first version, including the book catalogue, sign-in, wish lists, reviews, moderation tools, and setup notes.

StatusMVP · private

Not connected to a live Supabase project or deployment yet. The honest boundary is documented.

The problem

AI reports can sound confident even when a link does not support the claim. This library checks the source text before a claim appears in a report.

The approach

Each claim must match text found on a source page. The report keeps a quote with the claim, so readers can check where it came from.

How I check the sources

  • Independent checks. The system checks claims against saved source text instead of asking the same AI to verify its own answer.
  • Clear search results. It finds matching words and related passages, and keeps the results available for review.
  • Safer website checks. Links are checked before they are opened, and private network addresses are blocked.
  • Thorough checks. 1,124 automated tests include rules that catch unsafe code changes.

What is built — and what is not

The research library and its tests are ready. The part that runs the full workflow, plus the web API and command-line tool, are still future work. The public project is an early release.

StatusPublic · early release

Research library and tests are ready; the full app is still in progress.

The problem

Large tasks can get messy when one AI tries to do everything. This project gives each helper a clear job and brings their work together.

The approach

One helper gathers information, another reviews it, and others write and prepare a report. A central workflow passes the work from one step to the next.

How the helpers work

  • Clear jobs. Each helper has one task and its own instructions.
  • Work in order. A central workflow sends results to the next step.
  • Model choices. The system can use OpenAI or Gemini.
  • One clear result. The final response follows a consistent format.

What I built

I designed the helper roles, the order of work, and the connections to AI models. The project is built and tested, but it is not a public service.

The problem

Finding one detail in a long PDF can take a lot of reading. This project lets people ask a question and find the pages that can answer it.

How it works

  1. Read. Extract text from a PDF.
  2. Organize. Split long documents into smaller passages.
  3. Search. Find passages that match the question.
  4. Answer. Use those passages to help write a response.
  5. Check. Keep the source passages available so readers can review them.

What took care

PDFs can be long or hard to read. I had to split the text into useful sections and make sure search found the right passages.

My contribution

I built the PDF reader, document search, and answer flow that connects each answer to the matching text.
